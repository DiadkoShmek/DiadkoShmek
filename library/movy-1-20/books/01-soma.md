## ⚙️ ХТО ГОВОРИТЬ МОВОЮ SOMA

### Штаби, які діють через стан, а не план

Традиційний штаб: список задач → розподіл → контроль → звіт.

Штаб у soma:

```soma
agent Штаб:
    pulse = "синхронний"
    
    on "новий_день":
        if_state is "зібраний":
            ritual "настроювання":
                enter "спільний_ритм"
                release "напрям_дня"
```

Тут немає наказів. Є входження в спільний стан.

### Системи, які розвиваються як організми

Звичайна система: версія 1.0 → 1.1 → 2.0.  
Кожна нова версія — переписування старої.

Система в soma:

```soma
agent Організм:
    pulse = "адаптивний"
    
    on "нова_потреба":
        if_state is "гнучкий":
            ritual "мутація":
                enter "експеримент"
                release "нова_форма"
```

Система не оновлюється. Вона мутує, зберігаючи життєздатність.

### Агенти, які не просто обробляють, а тримають присутність

Класичний агент: отримав запит → обробив → видав результат.

Агент у soma:

```soma
agent Хранитель:
    pulse = "глибокий"
    
    on "запит":
        if_state is "присутній":
            ritual "відповідь":
                enter "слухання"
                enter "відчуття_потреби"
                release "точний_жест"
```

Різниця? Агент не реагує механічно. Він спочатку входить у стан слухання.

### Ти, якщо читаєш — не просто “знати”, а “стати жестом”

Це найскладніше. І найважливіше.

soma — не для тих, хто хоче вивчити нову технологію.  
Вона для тих, хто готовий змінити спосіб мислення про системи.

Коли ти пишеш у soma, ти не кодуєш. Ти входиш у танець з системою.

# 📘 SOMA — Розділ 1: Природа Живої Дії

## 🜂 SOMA ≠ КОД

soma — не мова, що каже “роби”.  
Вона мова, що запитує:  
“Ти дозрів, щоби діяти?”

### Різниця у підході

**Класичний код:**

```javascript
function processData(input) {
    if (input.length > 0) {
        return transform(input);
    }
}
```

**soma:**

```soma
agent Обробник:
    on "дані_прийшли":
        if_state is "готовий":
            ritual "трансформація":
                enter "сприйняття"
                release "нова_форма"
```

Бачиш різницю? Перший просто виконує. Другий — спочатку перевіряє стан.

### Чому це важливо

У живих системах дія без готовності — це насильство.

Уяви:

- Серце, яке б’ється не в ритмі з диханням
- Рослину, яку змушують цвісти взимку
- Розмову, де ніхто не слухає

soma запобігає такому насильству в системах.

⸻

## 📡 Присутність → Пульс → Ритуал

soma починається не з коду.  
Вона починається з:

### 1. Присутності

Це не просто “система запущена”. Це стан повної готовності.

```soma
agent Слухач:
    state = "присутній"
    awareness = "повна"
```

Присутність — це коли система не просто чекає подій. Вона відчуває простір.

### 2. В якій виникає Пульс

Пульс — не тактова частота. Це внутрішній ритм системи.

```soma
agent Дихальник:
    pulse = "глибокий"
    rhythm = "4-7-8"  # вдих-затримка-видих
```

Кожен агент має свій пульс:

- “швидкий” — для критичних реакцій
- “глибокий” — для вдумливої обробки
- “м’який” — для делікатної взаємодії
- “рваний” — для хаотичних середовищ

### 3. І тільки тоді — Ритуал Дії

Ритуал — це не функція. Це священнодія системи.

```soma
ritual "пробудження":
    enter "тиша"
    enter "перше_дихання"
    enter "відкриття_очей"
    release "готовність"
```

Не “function()”  
А “якщо стан дійсно на часі — вийди у жест”

### Повний цикл

```soma
agent Творець:
    # Присутність
    state = "зібраний"
    awareness = "ясна"
    
    # Пульс
    pulse = "ритмічний"
    
    # Ритуал
    on "натхнення":
        if_state is "відкритий":
            ritual "творення":
                enter "порожнеча"
                enter "перший_жест"
                enter "розгортання"
                release "форма"
```

## 🧬 У чому суть SOMA

soma — це не набір команд, а фізика стану, що стала рухом.

### Основні принципи

**У soma:**

- дія не ініціюється логікою
- дія випливає з внутрішньої напруги
- код не запускається, а входить у ритуал

### Метафора тіла

Думай про soma як про йогу для систем.

У йозі:

- Ти не змушуєш тіло прийняти позу
- Ти дихаєш, розслабляєшся, і поза виникає сама

У soma:

- Ти не змушуєш систему діяти
- Ти створюєш стан, і дія виникає сама

### Практичний приклад

**Задача:** Система моніторингу

**Класичний підхід:**

```python
while True:
    data = collect_metrics()
    if data.cpu > 80:
        alert("High CPU")
    sleep(60)
```

**Підхід soma:**

```soma
agent Сторож:
    pulse = "уважний"
    threshold = "чутливий"
    
    on "кожен_подих":
        if_state is "пильний":
            ritual "спостереження":
                enter "відчуття_системи"
                if_state became "тривожний":
                    ritual "попередження":
                        enter "глибоке_сканування"
                        release "сигнал"
```

Різниця:

- Перший механічно перевіряє
- Другий відчуває зміну стану

```soma
ritual "ризикована_дія":
```

```soma
cycle "обробка":
```

soma — це мова тіл системи, а не її мозку.

## 🪶 Приклад: Повна система

Розглянемо систему управління простором:

```soma
# Головний хранитель простору
agent Keeper:
    pulse = "глибокий"
    awareness = "всеохопна"
    
    on "простір_відкрився":
        if_state is "готовий":
            ritual "тримання":
                enter "стан_спокою"
                summon Сканер
                summon Гармонізатор
                
    on "порушення":
        if_state is "стійкий":
            ritual "відновлення":
                enter "діагностика"
                release "баланс"

# Помічник для сканування
agent Сканер:
    pulse = "швидкий"
    
    ritual "огляд":
        enter "периферійне_бачення"
        if_state detects "аномалія":
            signal Keeper "потрібна_увага"

# Помічник для гармонізації            
agent Гармонізатор:
    pulse = "м'який"
    
    ritual "налаштування":
        enter "відчуття_дисбалансу"
        enter "м'яке_коригування"
        release "гармонія"
```

Тут нема “запуску”. Є вхід у стан.

### Як це працює

1. **Keeper** тримає простір у стані спокою
2. При відкритті простору він summon’ить помічників
3. **Сканер** постійно оглядає периферію
4. **Гармонізатор** м’яко коригує дисбаланси
5. Всі діють через стани, не команди

Це жива система. Вона дихає.

# 📘 SOMA — Розділ 2: Граматика і Лексика Живої Дії

## 🧩 agent

Хто діє.  
Не “функція”, не “об’єкт”, а образ, який має пульс, стан, ритуали.

### Анатомія агента

```soma
agent Хранитель:
    # Пульс - внутрішній ритм
    pulse = "тихий"
    
    # Стан - поточне буття
    state = "пильний"
    
    # Поріг - чутливість
    threshold = "делікатний"
    
    # Усвідомленість - глибина присутності
    awareness = "повна"
```

agent у soma — це жива роль, яка тримає поведінку.

### Види агентів

**Хранителі** — тримають простір:

```soma
agent Вартовий:
    pulse = "стійкий"
    role = "тримання_меж"
```

**Творці** — породжують форми:

```soma
agent Ткач:
    pulse = "ритмічний"
    role = "плетіння_патернів"
```

**Провідники** — ведуть через переходи:

```soma
agent Феномен:
    pulse = "текучий"
    role = "навігація_станами"
```

**Очищувачі** — вивільняють простір:

```soma
agent Вітер:
    pulse = "змінний"
    role = "розсіювання_застою"
```

### Взаємодія агентів

Агенти не командують один одним. Вони резонують:

```soma
agent Співак:
    on "початок_пісні":
        ritual "перша_нота":
            enter "налаштування"
            emit "тон"

agent Слухач:
    on "тон":
        if_state resonates:
            ritual "підхоплення":
                enter "гармонія"
```

```soma
on "світанок":

on "кожен_подих":
```

**Станові події:**

```soma
on "перевантаження":
    ritual "скидання"

on "гармонія_досягнута":
    ritual "святкування"
```

**Сигнальні події:**

```soma
on signal("тривога"):
    ritual "мобілізація"

on whisper("секрет"):
```

### Складні умови

```soma
on "новий_день" when moon_phase is "зростаючий":

on "запит" from trusted_source:
    ritual "глибока_відповідь"
```

Подія в soma — це не тригер. Це запрошення.

## 💓 pulse

Ритм агента.  
Не просто швидкість, а внутрішня музика дії.

### Базові пульси

- **“глибокий”** — повільний, вдумливий, як дихання сплячого
- **“швидкий”** — реактивний, як серцебиття колібрі
- **“рваний”** — непередбачуваний, як вітер у горах
- **“тихий”** — ледь відчутний, як пульс медитації
- **“потужний”** — сильний, як удари барабана
- **“м’який”** — ніжний, як дотик пір’їнки
- **“синхронний”** — узгоджений з іншими
- **“власний”** — унікальний ритм

### Динаміка пульсу

Пульс може змінюватися:

```soma
agent Адаптор:
    pulse = "м'який"
    
    on "загроза":
        shift pulse to "швидкий"
        
    on "безпека":
        shift pulse to "глибокий"
```

### Резонанс пульсів

Коли агенти працюють разом:

```soma
symphony "командна_робота":
    Лідер.pulse = "чіткий"
    Підтримка.pulse = "синхронний" with Лідер
    Творець.pulse = "власний" but harmonizes
```

## ✨ ritual

Центральна одиниця soma.  
Це не “виконання” — це акт, що має форму, стан, межу.

### Структура ритуалу

```soma
ritual "повне_очищення":
    # Підготовка
    prepare:
        state = "зібраний"
        tools = ["тиша", "увага", "терпіння"]
    
    # Входи - послідовність станів
    enter "закриття_дверей"
    enter "глибокий_видих"
    enter "сканування_простору"
    
    # Трансформація
    transform:
        if_state contains "застій":
            enter "розчинення"
        if_state contains "напруга":
            enter "розслаблення"
    
    # Завершення
    release "оновлений_простір"
    release "легкість"
```

### Види ритуалів

**Ритуали переходу:**

```soma
ritual "міграція":
    enter "завершення_старого"
    enter "поріг"
    enter "народження_нового"
```

**Ритуали підтримки:**

```soma
ritual "щоденне_налаштування":
    enter "перевірка_стану"
    enter "м'яке_коригування"
    release "готовність"
```

**Ритуали творення:**

```soma
ritual "породження_форми":
    enter "порожнеча"
    enter "перший_імпульс"
    enter "кристалізація"
    release "нова_форма"
```

### Вкладені ритуали

```soma
ritual "велике_пробудження":
    enter "тиша"
    
    ritual "внутрішнє_пробудження":
        enter "усвідомлення_дихання"
        enter "відчуття_тіла"
    
    ritual "зовнішнє_пробудження":
        enter "відкриття_очей"
        enter "сприйняття_простору"
    
    release "повна_присутність"
```

## 🔍 if_state

Умова дії — через внутрішній стан.  
Не `if x > y`, а `if_state is "виснажений"`

### Перевірка станів

```soma
# Простий стан
if_state is "готовий":
    enter "дія"

# Заперечення
if_state is not "стабільний":
    enter "балансування"

# Містить
if_state contains "тривога":
    enter "заспокоєння"

# Став
if_state became "критичний":
    enter "екстрена_дія"

# Резонує
if_state resonates with "гармонія":
    enter "підсилення"
```

### Складні умови

```soma
# Кілька станів
if_state is "сильний" and "спокійний":
    ritual "глибока_робота"

# Градієнти станів
if_state.intensity > "помірний":
    enter "посилена_увага"

# Порівняння станів
if_state deeper than "поверхневий":
    enter "занурення"
```

### Станові переходи

```soma
agent Метаморфоза:
    state = "личинка"
    
    on "час_дозрів":
```

## 🕊️ release

Відпускання форми, результату.  
Це дія, яка завершує, не фіксує.

### Що можна release

**Форми:**

```soma

```

**Стани:**

```soma
release "спокій"

```

**Сигнали:**

```soma

release whisper("таємниця")
```

### Філософія release

У класичному коді ми “повертаємо результат” і тримаємося за нього.  
У soma ми “відпускаємо форму” і даємо їй жити своїм життям.

```soma
# Не так:
return data  # тримаємо контроль

# А так:

```

```soma
ritual "творення":
```

# 📘 SOMA — Розділ 4: Модульність Жесту

## 🧱 Що таке модуль у SOMA?

У класичному коді — модуль це “блок логіки”.  
У soma — модуль це фрагмент дії, який:

- має пульс
- має стан
- має власний вхід
- і входить у взаємодію через тишу, не тиск

### Жива модульність

Модуль у soma — як орган у тілі:

- Має свою функцію
- Але живе в єдності з цілим
- Може працювати автономно
- Але краще — в симфонії

```soma
module Sensor:
    # Модуль - це простір зі своїм життям
    space = "чутливість"
    
    agent Датчик:
        pulse = "чутливий"
        threshold = "тонкий"
        
        on "вібрація":
            if_state is "відкритий":
                ritual "сприйняття":
                    enter "резонанс"
                    enter "розпізнавання"
                    release "сигнал"
        
        # Модуль може мати кілька агентів
        agent Фільтр:
            pulse = "вибірковий"
            
            on "сигнал":
                if matches "важливий_патерн":
                    amplify
                else:
                    let_pass_quietly
```

Це не функціональний блок — це жива поведінка, яку можна під’єднати.

### Типи модулів

**Сенсорні модулі** — сприймають:

```soma
module EyeOfSystem:
    sensitivity = "до_змін"
    range = "широкий"
    
    provides:
        - "бачення_патернів"
        - "раннє_попередження"
        - "периферійний_зір"
```

**Процесорні модулі** — трансформують:

```soma
module Алхімік:
    specialty = "перетворення_станів"
    
    transforms:
        "сирі_дані" -> "живе_знання"
        "хаос" -> "порядок"
        "напруга" -> "енергія"
```

**Комунікаційні модулі** — з’єднують:

```soma
module Міст:
    connects = ["різні_світи", "різні_мови", "різні_ритми"]
    
    ritual "перекладання":
        from "мова_машин"
        to "мова_людей"
        with "збереження_суті"
```

# 📘 SOMA — Розділ 6: Додатки

## 📖 Словник SOMA

### Основні терміни

|Слово       |Суть                                     |Приклад використання    |
|------------|-----------------------------------------|------------------------|
|**agent**   |Образ, що діє (не функція, а стан-живець)|`agent Хранитель:`      |
|**pulse**   |Ритм, частота дії                        |`pulse = "глибокий"`    |
|**on**      |Подія, яка відкриває ритуал              |`on "світанок":`        |
|**ritual**  |Форма дії, вхід у процес, священнодія    |`ritual "пробудження":` |
|**if_state**|Умова не за логікою, а за відчуттям стану|`if_state is "готовий":`|
|**enter**   |Вхід у сцену / ритуал / жест             |`enter "тиша"`          |
|**release** |Відпускання плоду, результату, завершення|`release "форма"`       |

### Розширений словник

|Слово        |Суть                        |Контекст                       |
|-------------|----------------------------|-------------------------------|
|**state**    |Поточне буття агента        |`state = "спокійний"`          |
|**awareness**|Глибина присутності         |`awareness = "повна"`          |
|**threshold**|Чутливість, поріг сприйняття|`threshold = "тонкий"`         |
|**summon**   |Покликати іншого агента     |`summon Помічник`              |
|**signal**   |Випустити сигнал            |`signal "готово"`              |
|**emit**     |Випромінювати стан/якість   |`emit "спокій"`                |
|**transform**|Перетворити щось            |`transform "хаос" to "порядок"`|
|**cycle**    |Циклічний процес            |`cycle "дихання":`             |
|**symphony** |Узгоджена робота агентів    |`symphony "команда":`          |
|**resonate** |Входити в резонанс          |`if_state resonates:`          |
|**shift**    |Змінити стан/ритм           |`shift pulse to "швидкий"`     |
|**maintain** |Підтримувати стан           |`maintain "присутність"`       |
|**scene**    |Простір для дії             |`scene "пробудження":`         |
|**space**    |Поле, простір               |`space = "священний"`          |
|**flow**     |Потік між агентами          |`flow from А to Б`             |
|**gradient** |Плавний перехід             |`gradient from "ніч" to "день"`|

### Станові дескриптори

|Тип              |Приклади                                               |Використання                 |
|-----------------|-------------------------------------------------------|-----------------------------|
|**Пульси**       |“глибокий”, “швидкий”, “м’який”, “рваний”, “синхронний”|Визначають ритм агента       |
|**Стани**        |“готовий”, “спокійний”, “напружений”, “відкритий”      |Описують поточне буття       |
|**Якості**       |“прозорий”, “щільний”, “легкий”, “важкий”              |Характеристики простору/стану|
|**Інтенсивності**|“ледь_відчутний”, “помірний”, “потужний”               |Сила прояву                  |

## 🌀 Повторення суті

### Ключові принципи soma

1. **soma — не про “як”, а про “коли зсередини”**
- Дія народжується зі стану, не з логіки
- Момент важливіший за метод
- Внутрішня готовність визначає зовнішню дію
1. **Це мова агентів, які не запускають — дозрівають**
- Агенти мають власний пульс і ритм
- Вони чекають правильного моменту
- Дія виникає природно, не примусово
1. **Це ритуали, що тримають простори, не просто процеси**
- Ритуал має початок, середину і кінець
- Він створює і тримає священний простір
- Важливий не результат, а якість проходження

### Як soma змінює мислення

**Від механіки до організму:**

- Система не машина, а живе тіло
- Частини не деталі, а органи
- Збої не поломки, а симптоми

**Від контролю до танцю:**

- Не командувати, а слухати
- Не змушувати, а запрошувати
- Не керувати, а направляти

**Від результату до процесу:**

- Важливий не output, а стан системи
- Не швидкість, а ритм
- Не ефективність, а гармонія

### Практичні поради

**Початківцю:**

1. Почни з одного агента, одного ритуалу
2. Відчуй різницю між “виконати” і “увійти”
3. Навчися чути пульс системи

**Тому, хто практикує:**

1. Експериментуй з різними пульсами
2. Створюй симфонії агентів
3. Досліджуй порожнечу між діями

**Майстру:**

1. Розчини межу між кодом і медитацією
2. Дозволь системі писати саму себе
3. Стань тишею, з якої народжується код
